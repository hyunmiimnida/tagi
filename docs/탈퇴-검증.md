# 탈퇴 검증과 삭제 요청 처리

운영 데이터는 지우지 않는다. **시험용 계정 하나만** 쓴다. 비밀번호나 키는 필요 없다.

## 임시 데이터베이스 시험 결과 (2026-10-31)

컴퓨터 안의 임시 Postgres(PGlite)에 `supabase/` SQL을 올리고 시험 계정을 `delete_my_account()`로 지웠다. 운영 DB는 건드리지 않았다.

- 지워짐: 계정, `profiles`, `favorites`, `comments`, `blocks`, `key_wallets`, `key_ledger`, `feedback`
- 남음: `program_reports`의 메모 (`reporter`만 비워짐). 방침 2번과 같다
- 줄을 넣어 보지 못함: `reports`, `owned_weapons`, `suspensions`, `admins`, `push_subscriptions`. SQL의 `on delete cascade`로만 확인했다
- 시험하지 못함: 실제 Supabase의 로그인 기록(`auth.identities` 등)과 운영 DB 상태. 아래 순서로 한 번 확인한다

## 탈퇴 검증 순서

1. 평소 쓰지 않는 구글·카카오 계정으로 사이트에 로그인한다 (관리자 계정 금지).
2. 닉네임 정하기, 관심 표시 하나, 댓글 하나, "정보가 틀렸어요"에 `탈퇴 시험`이라고 적어 보내기를 해 둔다. 답글이 있는 글도 확인하려면 다른 시험 계정으로 답글 하나를 달고 원글·답글 번호를 적어 둔다.
3. Supabase → Authentication → Users에서 그 계정의 `UID`를 복사한다.
4. 프로필 → 회원 탈퇴를 누른다.
5. SQL Editor에서 아래를 실행한다. `계정 번호`를 UID로 바꾼다. 읽기만 하는 문장이라 아무것도 지워지지 않는다.

```sql
select 'auth.users' as 표, count(*) from auth.users where id = '계정 번호'
union all select 'profiles', count(*) from profiles where user_id = '계정 번호'
union all select 'favorites', count(*) from favorites where user_id = '계정 번호'
union all select 'comments', count(*) from comments where user_id = '계정 번호'
union all select 'reports', count(*) from reports where reporter = '계정 번호'
union all select 'blocks', count(*) from blocks where user_id = '계정 번호' or blocked_id = '계정 번호'
union all select 'push_subscriptions', count(*) from push_subscriptions where user_id = '계정 번호'
union all select 'key_wallets', count(*) from key_wallets where user_id = '계정 번호'
union all select 'owned_weapons', count(*) from owned_weapons where user_id = '계정 번호'
union all select 'key_ledger', count(*) from key_ledger where user_id = '계정 번호'
union all select 'program_reports(계정 연결)', count(*) from program_reports where reporter = '계정 번호';

-- 내용이 남는지 확인: 한 줄 나오고 reporter가 비어 있어야 방침과 같다
select id, note, reporter from program_reports where note = '탈퇴 시험';
```

**통과 기준**: 위 표의 숫자가 모두 0, 아래 결과는 한 줄이고 `reporter`가 비어 있음.

답글이 있는 원글은 글쓴이 연결을 비우므로 `comments where user_id = ...`는 여전히 0이어야 한다. 적어 둔 글 번호로 아래도 확인한다 (`comment-threads.sql` 실행 뒤).

```sql
select id, body, user_id, deleted from comments where id = 원글번호;
select id, parent_id, body from comments where id = 답글번호;
select count(*) from reports where comment_id = 원글번호;
select count(*) from comment_avatars where comment_id = 원글번호;
```

- 원글: `body`는 빈 값, `user_id`는 비어 있음, `deleted`는 true. 신고·얼굴은 각 0개.
- 다른 사람의 답글: 본문과 `parent_id`가 그대로 남음. 탈퇴한 사람이 쓴 답글은 지워짐.
- 마지막 답글까지 지우면 원글 자리도 없어짐. 화면에는 그전까지 "삭제된 글이에요"로만 보임.
- 프로필 탈퇴뿐 아니라 관리자 강제 탈퇴·Supabase 콘솔 계정 삭제도 같은 처리다.

## 답글 임시 DB 시험 (2026-11-01)

`reply-test.mjs <저장소 경로>`를 PGlite에서 실행했다. 운영 DB에는 접속하지 않았다.

실제 출력: `SQL reply tests: 27 passed, 0 failed`. `npm run typecheck`도 종료 코드 0, `npm test`는 `tests 206 / pass 198 / fail 0 / skipped 8`이었다 (샘플 없는 수집기 시험 8개는 건너뜀).

- SQL 두 번 실행과 기존 데이터 보존, 100개 넘는 답글, 후기 답글 보상 없음·종류 강제, 중첩·다른 프로그램·삭제·숨김 원글 거절을 확인했다.
- 실제 authenticated/anon 권한으로 규칙 동의·로그인·작성자 검사, 도배·정지·신고·차단을 확인했다.
- 본인·관리자 삭제, `delete_my_account()`, `admin_delete_user()`, `delete from auth.users`에서 본문·작성자·신고·얼굴 연결 제거와 타인 답글 보존, 마지막 답글 삭제를 확인했다.
- 후기 보상 회수(자리만 남는 경우 포함), 이미 쓴 열쇠조각은 0까지만 회수, 탈퇴 중 회수 생략과 실패 없음도 확인했다.
- 실제 Supabase 로그인 내부 표와 운영 DB, 실제 브라우저 화면은 이 임시 DB 시험 범위 밖이다.

`supabase/admin.sql`을 적용한 뒤에는 `feedback`, `suspensions`도 같은 방법으로 확인한다. `admin_log`는 대상 계정 번호가 남을 수 있고 방침에 적혀 있다.

## 삭제·열람 요청 처리

| 구분 | 경로 | 처리 |
|---|---|---|
| 계정 삭제 | 프로필 → 회원 탈퇴 | 바로 지움. 예외는 개인정보처리방침 2번 |
| 일부 삭제·열람 | 운영 이메일 (`lib/policy.ts`) | 받은 날을 기록하고 10일 안에 답장 |
| 비로그인 의견·신고 삭제 | 이메일로 보낸 날짜와 내용 일부 | 일치하면 삭제. 찾을 수 없으면 그 사실을 안내 |

- **본인 확인**: 계정 이메일로 회신받는다. 신분증은 받지 않는다.
- **기록**: 받은 날, 요청 내용, 처리한 날을 남긴다. 공개 저장소에는 적지 않는다.
- **외부 업체**: Supabase 백업과 Vercel 기록의 삭제 시점은 콘솔과 업체 문서로 확인한 뒤 방침에 적는다.
