# 캠퍼스모아 목표 디자인 기획 v2 — 대학생을 돕는 작은 길드

작성일: 2026.10.06 · 범위: 다음 목표 경험과 390×844 휴대폰 화면 설계 · 상태: 기획안, 미구현

> **한 줄 비전: 나에게 맞는 대학생 기회를 찾고, 준비하고, 지원한 경험을 남길 때까지 네 명의 작은 길드원이 곁에서 도와주는 캠퍼스모아.**

## 1. 서비스 방향과 길드 설정

학교 게시판 사이를 오가던 네 명의 작은 도트 캐릭터는 학생들이 좋은 기회를 발견하고도 준비할 것과 마감 날짜를 놓치는 모습을 보고, 대학생을 돕는 길드를 만들었어요. 찾아오는 공고를 살피는 궁수, 정보를 정리하는 마법사, 마감을 챙기는 기사, 준비와 경험 나누기를 돕는 성직자가 각자의 일을 맡아요. 길드는 학생 대신 지원하거나 결과를 결정하지 않아요. 필요한 순간에 짧게 안내하고, 선택과 기록은 학생에게 맡겨요.

세계관 설명은 이 한 문단과 온보딩의 짧은 소개로 끝낸다. 실제 메뉴는 `공고`, `지원 준비`, `내 일정`, `후기`처럼 기능 이름을 쓴다. 안내 문구는 평범한 존댓말로 쓰며 캐릭터를 이해하지 않아도 모든 기능을 이용할 수 있어야 한다.

### 이전 목표에서 이어 갈 것과 다시 정할 것

### 확인한 현재 기반

- `CLAUDE.md`와 지정된 캐릭터 파일을 기준으로, 관심 표시·개인 캘린더·학교/신분/학년/관심 분야 설정·하루 전 웹 푸시·반복 프로그램·묶음 후기 댓글이 이미 있다.
- 캐릭터는 `sit` 16×17칸, `peek` 16×14칸, 별 동작 24×17칸이다. 현재 감정별 얼굴 그림은 없고, 눈 깜빡임과 `?`·`!` 그림만 있다.
- 공식 모집/활동 기간은 날짜를 저장한다. **공식 마감 시각, 활동 요일·주당 시간, 참가비, 공식 준비물, 제출 여부는 현재 데이터로 확정할 수 없다.**
- 배경에서 학교 21곳으로 설명했지만, 작성 시점 `config/schools.json`에는 **18개 본교 + 4개 별도 캠퍼스 = 22개 설정 항목**이 있다. 영남권 7개·수도권 15개이며 캠퍼스가 포함된 수다. 화면에 고정 숫자 21/22를 넣지 않는다. 설정에서 본교와 캠퍼스를 따로 계산하고, 캠퍼스는 추가 대학으로 세지 않는다.
- 새 기능의 저장 구조는 아래에 제안한다. 이 문서는 코드·수집기·DB를 변경하지 않는다.

## 2. 캐릭터 역할 카드

### 기존 등장 위치와 새 역할의 연결

하단 탭의 캐릭터 배치는 `CLAUDE.md`의 결정대로 **홈=반짝 / 공고=든든 / 캘린더=온유 / 프로필=솔**을 유지한다. 탭에 앉은 캐릭터는 그 화면을 함께 보는 길드원이다. 그 화면의 모든 기능을 독점하는 표시가 아니다. 홈의 마감 안내에는 든든, 공고 목록의 탐색 안내에는 솔, 캘린더의 날짜 정리에는 반짝, 프로필 첫 카드에는 온유가 기존처럼 빼꼼한다.

- 사용자는 캐릭터를 누르지 않는다. `추천 기준`, `알림 설정`, `할 일 추가` 같은 평범한 버튼을 누른다.
- 소개에서만 별명과 담당을 함께 쓴다. 이후 `솔 · 탐색 안내`처럼 작은 라벨을 필요한 안내에만 붙인다.
- 기본·축하·걱정·모름은 **사용 맥락과 문구의 상태**다. 새 표정 스프라이트가 이미 있다고 가정하지 않는다. 기존 자세, `?`·`!`, 옆의 체크/안내 아이콘으로 표현한다.
- 축하에 별 동작을 새로 재생하지 않는다. 칼·화살·마법·빛기둥은 기존 관심 표시 동작에서만 쓴다.

## 3. 핵심 기능 9개

### 기능 1. 온보딩 — 내 길드원 소개

**목적:** 학교와 관심을 입력하면 어떤 도움을 받을 수 있는지 1분 안에 이해한다.

**화면 동작:** 학교 선택 → 신분·학년 → 관심 분야의 3단계. `1/3`처럼 진행 위치를 표시한다. 학교는 지역 탭과 검색을 제공하고, 별도 캠퍼스가 설정된 학교만 캠퍼스 선택을 연다. 학교는 1개, 신분은 재학생/휴학생/졸업생 중 1개, 학년은 기존 값 1~4학년 중 1개, 관심 분야는 설정의 분야 태그 중 최대 3개를 선택한다. 모든 단계에 `건너뛰기`를 둔다. 졸업생은 학년 입력을 숨긴다. 휴학생의 학년은 선택 사항이다.

마지막 단계 아래에 `내 길드원` 2×2 소개를 배치한다. `솔 · 기회 찾기`, `반짝 · 정보 정리`, `든든 · 마감 챙기기`, `온유 · 준비 돕기`. 모두 함께 소개하며 랜덤 배정·선호 캐릭터 선택은 없다. 시작 버튼은 `내 기회 보러 가기`, 설정을 생략했으면 `공고 둘러보기`다.

**캐릭터:** 학교·관심을 안내하는 솔이 주 안내자. 소개에서 네 명이 작은 `sit`으로 등장한다. 알림 권한을 여기서 요청하지 않는다.

**상태·예외:** 학교 검색 0개는 `찾는 학교가 없어요. 학교 추가를 요청하거나 먼저 둘러보세요.`와 기존 의견 보내기 연결. 설정 로딩은 선택 칩 스켈레톤, 실패는 `학교 목록을 불러오지 못했어요` + `다시 시도` + `설정 없이 둘러보기`. 마지막 저장 실패는 입력을 유지하고 `설정을 저장하지 못했어요` + 재시도. 단순 미입력을 오류로 표시하지 않는다.

**데이터:** 기존 학교 설정, `profiles.school_id/status/grade/interests`. 캠퍼스는 해당 캠퍼스 학교 id를 `school_id`에 저장한다. 새 `onboarding_completed_at`, `onboarding_version`으로 완료/건너뛰기 후 반복 노출을 막는다. 비로그인 설정은 현재 브라우저 저장을 이어 쓴다.

**성공 지표:** 온보딩 시작 세션 중 시작/둘러보기 버튼까지 도달 비율 70% 이상, 완료자의 소요 시간 중앙값 60초 이하. 강제 입력으로 완료율을 높이지 않는다.

### 기능 2. 홈 — 오늘의 브리핑과 근거가 보이는 추천

**목적:** 오늘 확인할 일과 발견할 기회를 한 번에 고른다.

**화면 동작:** 브리핑은 최대 3줄이다. 순서는 `오늘 기한인 개인 할 일 N개` → `3일 안 마감 N개` → `새 맞춤 공고 N개`. 할 일 0개는 그 줄을 생략하며 모두 없으면 `오늘 급하게 챙길 일정은 없어요.`를 보여 준다. 숫자는 각각 내 기록과 실제 결과에서 계산한다. 마감 수는 관심/준비 단계만 센다.

추천은 학교·캠퍼스 범위와 openTo 포함 여부를 먼저 적용한다. 알려진 학년/신분 조건에서 명백히 제외된 항목은 기본 추천에서 뺀다. 남은 항목에서 관심 분야 일치를 우선하고, 같은 순위에서는 처음 수집한 시각 내림차순, 동률이면 id순으로 정렬한다. `3학년 · 취업·채용 관심으로 추천`처럼 실제로 확인한 근거 최대 2개를 쓴다. 대상 정보가 없으면 `대상은 원문 확인 필요`를 함께 표시한다. 전공·직무·활동 시간에 맞는다는 표현은 쓰지 않는다.

새 공고는 **최근 7일 처음 수집한 공고**로 정의한다. 원문이 방금 올라왔다는 의미가 아니며, 섹션 설명은 `최근 7일 새로 모은 공고`다. 홈 카드에는 첫 3개를 보여 주고 `더 보기`로 같은 조건의 공고 목록을 연다. `추천 기준`에서 프로필 항목을 수정할 수 있다.

**캐릭터:** 반짝이 브리핑 위 `peek`, 마감 임박에는 든든, 새 공고에는 솔. 한 화면 안에서 실제로 보이는 캐릭터 수 제한은 디자인 규칙을 따른다.

**상태·예외:** 설정 없음은 `학교와 관심 분야를 고르면 더 잘 골라 드려요.` + 내 정보. 추천 0개는 `지금 조건에 맞는 공고가 없어요.` + `지역 전체 보기`. 부분 로딩은 브리핑 숫자를 `0` 대신 짧은 스켈레톤으로 표시. 공고 실패와 개인 기록 실패를 분리해 정상 영역은 유지한다. 오프라인은 `마지막으로 받은 정보예요. 최신 마감은 원문에서 확인해 주세요.`. 특정 학교의 마지막 수집 성공이 3일 넘었으면 학교 이름과 실제 시각을 표시한다.

**데이터:** 기존 공고, 프로필, 관심, `firstSeenAt`(없으면 기존 수집 시각 대체), 수집 로그. 새 지원 기록과 개인 할 일. 상세 수집 시각과 목록의 `seen`을 원문 재확인 시각으로 둔갑시키지 않는다.

**성공 지표:** 브리핑 노출 세션 중 할 일/마감/새 공고 중 하나를 연 비율 35% 이상. 추천 노출 세션 중 상세 방문 비율 30% 이상. 대상 정보가 불명확한 추천의 확인 필요 라벨 누락 0건.

### 기능 3. 공고 탐색 — 지역·학교·캠퍼스·필터

**목적:** 현재 수집한 범위에서 원하는 기회를 찾고, 지원 범위와 정보의 빈칸을 이해한다.

**화면 동작:** 검색 범위는 제목·주최·요약·태그. 띄어 쓴 단어는 모두 포함되는 현재 검색 규칙을 유지한다. 학교 패널은 영남권/수도권 등의 설정 기반 지역 탭 → 학교 → 설정된 캠퍼스 순서다. `영남권 전체`는 그 지역 출처 학교 공고를 모으며 프로필 학교는 바꾸지 않는다. **개별 학교 또는 캠퍼스를 고르면 현재 서비스처럼 내 학교 설정도 저장**한다. 적용 전에 `학교를 고르면 내 학교 설정에도 저장돼요.`를 표시하고, 적용 후 `내 학교를 영남대로 바꿨어요 · 되돌리기`를 제공한다. 이전 기획의 ‘탐색 학교와 소속 학교 분리’는 이번에는 적용하지 않는다.

캠퍼스가 있는 학교는 `학교 전체 / 본교 / 별도 캠퍼스 / 캠퍼스 미확인 포함`을 제공한다. ‘본교’는 설정의 본교 항목을 뜻하며 활동 장소 확정을 뜻하지 않는다. 분류할 근거가 없는 공고는 `캠퍼스 미확인`으로 남긴다. 영남대·경북대처럼 별도 캠퍼스 설정이 없는 학교에 임의의 캠퍼스 선택지를 만들지 않는다. 동국대 WISE처럼 다른 지역인 캠퍼스는 해당 항목의 `region`을 따른다.

필터는 분야·활동 형태·주최 유형·신분·학년·설정된 교내 기관·신청 없이 참여·다른 학교도 지원·마감 포함이다. 태그는 같은 카테고리 안 OR, 다른 카테고리끼리 AND. `다른 학교도 지원`은 기본 켜짐이며 기존 `open=0` 의미를 유지한다. openTo 문구는 지원 대상 설명이지 모든 자격을 통과했다는 보증이 아니다. 지역 탭은 활동 장소 필터가 아니다.

시트 안 변경은 임시 상태로 두고 `공고 N개 보기`에서 적용한다. 닫기/뒤로가기는 취소. 검색·학교·지역·태그·정렬은 URL에 보존하고 상세 복귀 시 목록 위치를 복원한다. 목록은 기존처럼 30개씩 표시한다. 정렬은 `마감순 / 최신순`, 날짜 미확인은 마감순 맨 뒤다.

**캐릭터:** 솔이 목록 전체의 상단 `peek`. 각 공고 행에는 캐릭터가 없다. 필터 시트에는 추가 캐릭터를 넣지 않는다.

**상태·예외:** 결과 0개는 실제 재계산으로 `취업·채용 조건을 빼면 7개가 있어요.` 같은 버튼을 최대 2개 제안한다. 그런 결과가 없으면 `필터 초기화`. 로딩은 3행 스켈레톤, 실패는 반짝 `!` + `공고를 불러오지 못했어요` + 재시도. 설정 저장 실패는 목록 임시 선택을 유지하면서 `학교 설정 저장 실패 · 다시 저장`을 표시한다. 미확인 학년/신분은 원문 확인 대상으로 유지하고 명시적 제외 조건과 구분한다.

**데이터:** 공고 제목/주최/유형/기간/태그/대상/openTo/noApplication/campus, 학교 `region/campuses/campusOf/units`. 새로 필요한 것은 필터 UI의 임시 상태와 복귀 위치뿐이다. 캠퍼스 근거가 부족한 항목은 추측 없이 미확인으로 파생한다.

**성공 지표:** 필터 적용 세션 중 상세 방문 비율 40% 이상. 결과 0개 세션 중 조건 완화 후 상세 방문 비율 20% 이상. 개별 학교 변경이 프로필에 반영됨을 안내한 비율 100%.

### 기능 4. 공고 상세 — 요약·대상·지난 회차 판단

**목적:** 중요한 사실을 빠르게 읽고 원문에서 최종 지원 조건을 확인한다.

**화면 동작:** 게시 학교/캠퍼스와 주최를 따로 표시 → 제목 → 모집 상태 → 한 줄 요약 → 대상/기간 → 지원 준비 → 지난 공고/후기 → 출처 순서. `summary`가 있으면 저장된 60자 이내 요약을 표시하고 `AI가 정리한 요약` 보조 라벨을 붙인다. 화면을 열 때 AI를 새로 호출하지 않는다. 요약이 없으면 `한 줄 요약이 없어요. 원문 내용을 확인해 주세요.`.

대상은 `입력한 학교·학년 조건과 일치 / 대상 확인 필요 / 명시된 조건과 다름`을 글자로 구분한다. 일치는 저장된 항목에 한정하고 `최종 지원 자격은 원문에서 확인해 주세요.`를 함께 쓴다. 배열이 비어 있으면 ‘저장된 제한 정보 없음’으로 해석하며, 추출되지 않은 조건까지 없다고 단정하지 않는다. 단과대학·학과 대상은 해당 공고의 값을 그대로 보여 주되 사용자 전공을 새로 추정하지 않는다.

`seriesId`가 있으면 같은 학교 범위에서 묶인 지난 공고를 최신 회차부터 최대 3개, `모두 보기`로 전체 표시한다. `2025년 가을` 같은 라벨은 제목·날짜로 확인할 수 있을 때만 사용한다. 아니면 `2025.10 모집 공고`, 날짜도 없으면 공고 제목을 사용한다. 다음 회차의 게시 시점·인원·자격을 예측하지 않는다.

하단 주요 행동은 `원문에서 신청 방법 확인 ↗`. 복수 원문이면 출처명 목록을 열어 선택한다. 새로운 탭에서 열며 서비스 상세는 남긴다. 링크 방문만으로 제출 처리하지 않는다. 모집 종료에도 `원문 보기`를 유지한다. 원문 링크는 학교 설정/저장된 링크에서 가져온다.

**캐릭터:** 반짝이 요약 섹션 `peek`. 지원 준비로 이동하면 온유로 안내자를 전환한다. 같은 상세의 섹션마다 동시에 캐릭터를 추가하지 않는다.

**상태·예외:** 날짜만 있으면 `10.09 마감 · 시각은 원문 확인`, 당일은 `오늘 마감 · 시각 확인 필요`이고 분/초 카운트다운은 없다. 날짜가 없으면 `마감일 미확인`이며 D-day를 숨긴다. 모집 시작 전은 `10.01 모집 시작`, 날짜상 종료는 `모집 기간 종료`로 표시한다. `noApplication=true`이고 모집 기간이 없으면 `신청 없이 참여할 수 있어요`와 `운영 기간`, 주요 행동은 `원문에서 참여 방법 확인 ↗`. 운영 기간도 없으면 `운영 기간 미확인`.

합쳐진 id는 기존 aliases/moved 매핑으로 새 상세에 연결하고 개인 기록도 정규 id에 합친다. 보관함 항목은 보관 안내와 원문/현재 회차를 보여 준다. 원문이 열리지 않으면 서비스가 성공 여부를 검사했다고 표시하지 않고 `원문이 열리지 않나요? 다른 출처 보기 / 정보 오류 알리기`를 제공한다. 후기만 실패하면 공식 정보는 유지한다.

**데이터:** 기존 Program, 링크/출처, `seriesId`, archive/ids/aliases. 현재 없는 공식 서류는 기능 5에서 일반 안내와 분리한다. 공식 마감 시각 추가는 후순위이며 도입 전까지 기존 날짜 모델로 동작한다.

**성공 지표:** 상세 방문 세션 중 원문 버튼 선택 비율 25% 이상. 날짜 미확인 공고의 D-day 노출 0건. 공식 정보와 개인 기록의 라벨 누락 0건.

### 기능 5. 지원 준비 — 일반 확인과 개인 할 일

**목적:** 저장한 공고를 작은 준비 행동으로 바꾼다.

**화면 동작:** `준비 시작`을 누르면 관심 저장과 함께 준비 단계로 진입한다. 기본 항목은 `원문 지원 자격 확인`, `활동 기간과 내 일정 확인`, `원문 신청 방법·필요 서류 확인`의 3개다. 라벨은 `기본 확인 항목`; 공고 주최가 요구한 공식 준비물로 표시하지 않는다. 체크는 사용자 확인이며 원문 클릭으로 자동 완료하지 않는다.

`+ 내 할 일 추가`에서 제목 1~80자, 메모 최대 300자, 준비 기한 선택, 알림 없음 안내를 제공한다. 공고당 개인 항목 최대 20개. 기한은 날짜만 또는 날짜+시각이며 기본 시각을 몰래 채우지 않는다. 모집 마감 뒤 날짜를 고르면 `모집 마감일 뒤의 준비 기한이에요. 그대로 저장할까요?`를 표시하고 직접 저장할 수 있다. 개인 기한은 공식 마감과 분리한다. 첫 버전은 개인 기한 웹 푸시를 제공하지 않고 홈/내 일정에 표시한다.

진행은 `2/5 완료`처럼 전체 체크 항목 기준이다. 완료 항목도 읽을 수 있게 남긴다. 삭제 시 분모를 다시 계산한다. 체크를 모두 마쳐도 `준비 항목을 모두 확인했어요. 제출은 원문에서 진행해 주세요.`만 표시한다. 제출 버튼이나 제출 기록을 자동 실행하지 않는다. 새 회차로 체크 완료를 복제하지 않는다.

후기의 `내 할 일로 추가`는 해당 팁을 개인 항목으로 넣고 `후기에서 가져온 내 할 일 · 공식 준비물 아님`을 표시한다. 본문 전체를 자동 복사하지 않고 사용자가 고른 짧은 항목명과 후기 연결 id만 저장한다.

**캐릭터:** 온유 `peek`, 다음 미완료 항목 1개 안내. 막혔을 때는 `필요 서류를 아직 모르겠다면 원문 확인부터 해요.`. 취업 상담을 원하는 경우 상담·심리/멘토링 태그의 공고 탐색으로 연결하며 상담 채팅을 제공하지 않는다.

**상태·예외:** 아직 시작 전은 `원문 확인부터 준비해 볼까요?` + 준비 시작. 저장 중 해당 체크만 진행 표시하고 중복 누름을 막는다. 저장 실패 시 마지막 확정 상태로 복원하고 `체크를 저장하지 못했어요 · 다시 시도`. 다른 화면에서 데이터가 바뀌면 최신 저장 내용을 반영한다. 오프라인은 기록 읽기만 제공하고 `온라인에서 준비 기록을 바꿀 수 있어요.`. 기한을 입력하지 않은 할 일은 `기한 없음` 그룹에 둔다.

**데이터:** 새 `applications`, `preparation_tasks`에 개인 단계·항목·완료·개인 기한을 저장한다. 기본 항목은 버전 있는 서비스 템플릿이며 사용자의 완료 상태는 개인 데이터다. 후속 공식 서류 도입 시 출처 링크와 확인 날짜가 있는 구조화 필드를 따로 마련한다.

**성공 지표:** 준비 시작한 공고 중 7일 안에 기본 확인 항목 1개 이상 완료 비율 60% 이상. 준비 시작 후 14일 안에 사용자 제출 기록 비율 30% 이상. 이 비율은 실제 외부 제출률로 표현하지 않는다.

### 기능 6. 내 일정 — 지원 단계와 캘린더

**목적:** 관심부터 결과까지 이어 보고 공식 기간과 개인 기한을 구분한다.

**화면 동작:** 화면 제목 `내 일정`, 하단 탭 이름은 기존 `캘린더`. 단계 칩 `전체 / 관심 / 준비 / 제출 / 결과`, 보기 전환 `할 일 / 캘린더`. 관심 표시는 관심 단계의 진입이다. 준비 시작·제출 기록·결과 기록은 사용자 행동으로만 바뀐다. 기본은 할 일 보기의 오늘+다가오는 7일, 월간 캘린더는 보기 전환으로 연다. 모집 마감, 활동 기간, 개인 준비 기한을 각각 라벨과 점/선으로 구분한다.

| 단계/상황 | 진입 행동 | 표시와 알림 |
|---|---|---|
| 관심 | 별 저장 | `준비 시작 전`, 마감 알림 가능 |
| 준비 | 준비 시작 또는 개인 할 일 생성 | `2/5 완료`, 마감 알림 가능 |
| 제출 | `제출 기록`에서 본인이 확인 | `제출 완료 · 본인 기록`, 이후 마감 푸시 중단 |
| 결과 | 결과를 직접 기록 | `선발 / 미선발 / 지원 중단 / 직접 입력`, 마감 푸시 중단 |
| 제출 후 수정 | 단계 메뉴에서 준비로 되돌리기 | `준비로 되돌렸어요`, 다음 예약일부터 알림 재개 |
| 기간 종료·미제출 | 날짜가 지난 상태 | 현재 단계 유지 + `모집 기간 종료`, 자동 미선발 처리 없음 |

제출 기록의 날짜는 기본 오늘, 과거 날짜로 수정 가능하며 미래 날짜는 막는다. 바로 제출로 건너뛸 수 있지만 `원문에서 제출을 마친 공고인가요?`를 확인한다. 원문 복귀 시 자동 팝업 대신 상세의 `제출하셨나요? 제출 기록` 안내를 한 번 보여 준다. 결과 확인 날짜는 사용자 선택이며 공고 데이터에서 만들어 내지 않는다.

신청 없이 참여 공고는 제출 단계를 숨기고 관심/준비에서 `참여 기록`으로 결과 단계에 바로 이동한다. `참여했어요 / 참여하지 않았어요`로 기록하며 지원 통계에서 제외한다. 활동 기간을 지원 마감으로 알리지 않는다.

별을 해제해도 준비·제출·결과 기록은 유지한다. 일정의 관심 목록에서는 빠지고 `기록이 남은 공고`에 남는다. 개인 기록 삭제는 별 해제와 다른 행동이며 무엇을 지울지 설명한 뒤 확인한다. 지난 관심 공고는 archive/ids를 통해 제목·원문·이번 회차를 표시한다. 새 회차는 새 공고로 저장하며 지난 제출·결과는 유지한다.

기존 .ics 내보내기를 유지하고 개인 기한 포함 여부를 선택하게 한다. 파일에는 본인 메모/후기를 넣지 않는다. .ics는 복사된 일정이며 파일을 다시 내보내기 전에는 수정이 반영되지 않는다고 안내한다. 기존 하루 전 오전 9시 캘린더 알림과 웹 푸시는 별개임을 표시한다.

**캐릭터:** 할 일 카드에 온유 `peek`, 달력 보기의 날짜 정리에 반짝 `peek`, 캘린더 탭에는 온유 `sit`. 보기 전환 시 본문 안내자 1명만 바뀐다.

**상태·예외:** 관심 0개는 `관심 공고를 저장하면 일정이 보여요.` + 공고 찾기. 선택 날짜 0개는 `이날은 저장된 일정이 없어요.`. 지원 기록 실패는 기존 공고 일정은 보여 주고 `지원 기록을 불러오지 못했어요`. 공식 기간이 없는 항목은 달력에 가짜 날짜를 넣지 않고 `날짜 미확인` 목록에 남긴다. 기간이 같은 날짜에 겹쳐도 시간 정보가 없으므로 `활동 기간이 겹쳐요. 시간은 원문에서 확인해 주세요.`까지만 안내한다.

**데이터:** 기존 관심, 모집/활동 기간, archive/ids/moved, 새 applications와 preparation_tasks. official date와 personal due를 서로 덮어쓰지 않는다.

**성공 지표:** 준비 단계 공고를 가진 주간 이용자 중 내 일정 이용 비율 50% 이상. 제출 기록 저장 성공 비율 99% 이상. 외부 링크 방문에 의한 자동 제출/결과 변경 0건.

### 기능 7. 마감 알림 — 3일 전·하루 전·당일 웹 푸시

**목적:** 사용자가 선택한 관심 공고의 마감을 챙기면서 이미 제출한 공고를 반복 재촉하지 않는다.

**화면 동작:** 내 정보에서 `이 기기에서 마감 알림 받기`를 누르면 `관심·준비 중인 공고의 마감을 오전 9시에 알려 드려요.`를 먼저 설명하고, 사용자가 계속을 눌렀을 때만 브라우저 권한을 요청한다. 로그인 가능한 서비스에서는 로그인 필요. 선택지는 `3일 전 / 하루 전 / 당일`, **초기 기본은 기존처럼 하루 전만 선택**이다. 최소 1개를 선택하며 마지막 선택을 끄려 하면 `마감 알림 끄기`로 처리한다.

발송 기준은 Asia/Seoul 날짜와 오전 09:00. 등록된 기기별 하루 최대 1건의 묶음 푸시로 보낸다. 예: `오늘 마감 1개 · 하루 전 2개` / `관심 공고의 마감일을 확인해 주세요.`. 공고 하나면 제목을 사용한다. 잠금 화면에는 닉네임·학년·개인 할 일·제출 결과를 넣지 않는다. 묶음 푸시 클릭은 내 일정의 마감 목록, 단일 푸시는 공고 상세로 연결한다.

**발송 규칙:** 마감 날짜가 있는 관심/준비 공고만 대상. 제출/결과·관심 해제·날짜 미확인·모집 기간 없는 신청 없이 참여 공고는 제외한다. 공식 시각은 모르므로 당일 알림에도 `마감 시각은 원문 확인`을 포함한다. 오전 9시 전에 이미 닫히는 공고를 확실하게 막을 수 없다는 한계를 설정 설명에 둔다. 시각을 확보한 후에만 더 정밀한 정책을 검토한다.

발송 작업이 늦으면 당일 09:00~12:00 안에서 재시도하고 이후는 오래된 푸시를 보내지 않는다. `사용자+기기+공고+마감 날짜+알림 기준일`로 중복 방지한다. 09:00 이후 알림을 켠 사람에게 지난 알림을 몰아서 보내지 않는다. 날짜가 연장되면 다음 발송은 최신 날짜를 따르되 별도 ‘마감 변경 알림’은 아직 제공하지 않는다. 날짜 재수집 자체가 항상 이루어지는 것은 아니므로 변경 감지 보장을 하지 않는다.

**캐릭터:** 든든이 알림 설정을 설명하는 `sit`. 푸시 권한 허용을 보상·배지와 연결하지 않는다.

**상태·예외:** 사용 중 / 꺼짐 / 권한 확인 중 / 이 기기 차단 / 다른 기기에서만 사용 / 미지원 / 등록 실패를 구분한다. 대상 공고 0개는 `지금 알릴 마감이 없어요. 관심 공고를 저장하면 알려 드려요.`로 표시하고 알림 설정은 유지한다. 권한 확인·기기 등록 중에는 해당 버튼만 진행 표시하며 다시 누름을 막는다. 차단은 `이 기기의 알림이 차단돼 있어요. 브라우저 설정에서 허용해 주세요.`. 다른 기기는 기존 `이 기기에서도 받기`. iOS 등 설치 조건이 필요한 환경은 감지된 조건에 맞춰 홈 화면 추가 안내를 제공한다. 미지원이면 .ics와 내 일정으로 안내한다. 토글은 구독 저장이 성공한 뒤 켜짐으로 확정한다. 기기 확인 알림은 구독 완료 시 1회이며 정기 발송과 구분한다. 알림 끄기는 즉시 해당 기기 구독을 해제하고 다른 기기 알림까지 해제하지 않는다.

푸시 발송 성공은 브라우저 전달 요청이 받아들여졌다는 뜻이다. 실제 표시·열람·정확한 시각 도착을 보장하지 않는다. 실행 상태만 `오늘 발송 작업 지연`으로 안내할 수 있으며 ‘학생이 알림을 받았다’고 표시하지 않는다.

**데이터:** 기존 profiles.notify_deadline, push_subscriptions, 발송 작업을 확장한다. 새 기기별 알림 offsets/enabled, 중복 방지 발송 기록, 발송 작업 상태와 만료 구독 정리 정보. 기존 알림 사용자의 유효한 구독은 하루 전만 선택한 상태로 이전하고, 꺼 둔 구독을 자동으로 켜지 않는다. 서버에서 지원 단계와 관심을 확인한다. 기기 주소/비밀 키를 브라우저 공개 데이터에 포함하지 않는다.

**성공 지표:** 알림 등록 시도 중 지원 기기의 등록 성공 비율 95% 이상. 발송 대상 묶음 중 09:00~12:00 안 요청 성공 비율 99% 이상. 동일 기기의 중복 푸시 0건, 제출/결과 단계에 대한 발송 0건. 열람률은 별도 클릭 기록이 있을 때만 측정한다.

### 기능 8. 후기 — 회차별 경험 나누기

**목적:** 같은 프로그램의 지난 경험을 이번 준비의 참고로 읽는다.

**화면 동작:** 상세의 `지난 공고·후기` → 회차별 후기 화면. 상단에 프로그램명과 `이번 회차 / 지난 회차 / 회차 미지정` 선택. 새 후기 작성은 회차 공고 선택 필수, 유형 `준비 팁 / 참여 후기 / 질문`, 본문 1~500자. 선택 입력은 결과 `선발 / 미선발 / 참여 / 응답 안 함`, 준비 기간 `1~3일 / 4~7일 / 8~14일 / 15일 이상 / 기억 안 남`. 모두 작성자 입력이며 `참여 인증`·공식 합격 인증 배지는 없다. 한 회차 안 기본 정렬은 최신순이다.

기존 `series_id` 댓글은 그대로 보존하고 `회차 미지정`에 둔다. 작성자 본인이 로그인해서 자신의 글에 회차를 붙일 수 있지만 운영자가 내용을 보고 자동 배정하지 않는다. 묶음 없는 단일 공고도 해당 program_id로 질문/후기를 작성할 수 있게 저장 구조를 확장한다. 잘못된 series 묶음이 나중에 수정되어도 program_id 기준 후기 귀속을 유지한다.

후기 카드에는 회차·유형·닉네임·작성일·작성자 입력 결과를 표시한다. 본문을 누르면 전체를 펼치고, 준비 팁에서 `내 할 일로 추가`를 누르면 개인 항목명을 입력하는 작은 시트를 연다. 친구 공유는 기존 공고 링크 공유만 사용한다.

**캐릭터:** 온유 `peek` 또는 후기 0개에서 `sit`. `지난 회차의 경험이에요. 이번 원문 조건도 확인해 주세요.`를 설명한다.

**상태·예외:** 후기 0개는 `아직 이 회차의 후기가 없어요.` + `다른 회차 보기 / 후기 쓰기`. 로그인 전 읽기는 가능, 쓰기는 로그인 후 초안 복원. 로딩은 2개 카드 스켈레톤, 실패는 `후기를 불러오지 못했어요` + 다시 시도. 전송 실패는 초안을 유지한다. 기존 제한인 20초 재작성 간격·하루 20개·반복 내용·링크 2개 이상 차단을 유지하며 해당 이유를 설명한다. 정지 기간 안내, 신고/숨김, 본인 글 삭제를 유지한다. 숨긴 글은 집계에서도 제외하며 다른 작성자의 id를 공개하지 않는다.

**데이터:** comments에 program_id, kind, self_reported_result, preparation_duration을 추가하고 공개 읽기 뷰에도 허용된 항목만 추가한다. 기존 댓글의 program_id는 null 허용. 단일 공고는 series_id null 허용이 필요하다. 집계는 현재 회차 매핑으로 계산한다. 서버가 program_id와 series_id의 관계를 검증한다.

**성공 지표:** 후기 열람 세션 중 원문 또는 준비 목록으로 이동 비율 25% 이상. 새 후기 중 회차 연결 저장 비율 100%. 기존 미지정 글의 자동 회차 추정 0건, 사용자 id 공개 0건.

### 기능 9. 내 정보·알림 설정 — 내가 받을 도움 조절하기

**목적:** 추천 정보와 기기 알림 상태를 이해하고 직접 수정한다.

**화면 동작:** 닉네임/로그인 방식 → 관심·준비·제출·내 후기 수 → 학교/캠퍼스/신분/학년/관심 분야 → 기기 마감 알림 → 캘린더 내보내기·동작 줄이기 → 내 글·의견·규칙·계정 순서다. 관심 분야는 온보딩 이후에는 현재 설정 목록 안에서 여러 개 선택할 수 있다. 학교를 바꿔도 지난 관심/지원/후기를 지우지 않고 추천과 기본 필터만 바꾼다. 졸업생으로 변경 시 학년을 추천에 적용하지 않는다.

`내 길드원 소개`는 텍스트 버튼으로 작은 소개 시트를 열고 네 명의 역할만 보여 준다. 도감·배지·캐릭터 능력 설정은 아니다. `캐릭터 동작 줄이기`는 기기 동작 줄이기가 켜졌으면 강제로 적용하고, 꺼졌으면 사용자가 이 서비스에서만 추가로 끌 수 있다. 기본은 기기 설정 따름. 색 모드는 기존 자동 다크 모드를 유지한다.

**캐릭터:** 첫 카드에 온유 `peek`, 프로필 탭에 솔 `sit`. 알림 섹션이 보이는 동안 첫 카드 캐릭터가 화면 밖이면 든든 안내를 표시할 수 있다.

**상태·예외:** 미로그인은 `로그인하면 준비 기록을 다른 기기에서도 이어 볼 수 있어요.`. 로그인 제공 환경에서 관심/지원 저장 시 로그인 시트를 열며, 계정 연결 자체가 없는 체험 모드에서만 로컬 저장을 제공한다. 체험 모드는 `이 브라우저에만 저장돼요. 기기 알림과 후기 작성은 사용할 수 없어요.`. 체험 기록을 로그인 계정으로 가져올 때 합칠 기록 수를 먼저 보여 주고 선택하게 한다. 실패 시 로컬 사본을 지우지 않는다. 설정 로딩은 값 대신 스켈레톤, 실패는 기존 값을 유지하고 다시 저장. 탈퇴 시 삭제될 개인 기록을 명시하고 기존 탈퇴 절차를 따른다.

**데이터:** 기존 profiles/기기 구독/내 댓글/의견/차단, 새 단계별 집계. 동작 설정은 기기 로컬 저장. 공개 공고 파일이나 git에 개인 정보를 넣지 않는다.

**성공 지표:** 설정 변경 요청 중 저장 성공 비율 99% 이상. 지원되는 기기의 알림 상태/권한/구독 불일치 1% 미만. 체험 기록 가져오기 실패 시 로컬 기록 손실 0건.

### 공통 일관성·보안 규칙

1. 개인 표는 로그인한 본인만 읽고 수정한다. 공개 후기에는 닉네임과 허용된 경험 정보만 노출하고 user_id는 기존처럼 숨긴다. 신고·차단·정지 검사는 새 후기 입력에도 적용한다.
2. applications와 준비 항목 변경은 버전으로 충돌을 확인한다. 다른 기기의 새 기록을 덮어쓰려 하면 `다른 기기에서 바뀐 기록이 있어요. 최신 내용을 확인해 주세요.`와 다시 불러오기를 제공한다.
3. 별 해제는 favorites만 변경한다. 개인 기록 전체 삭제는 별도 행동이다. 탈퇴는 기존 삭제 관계에 새 개인 표도 포함한다.
4. aliases로 id가 합쳐지면 관심·지원·할 일·후기의 참조를 정규 id로 이동한다. 서로 다른 제출/결과 기록이 충돌하면 사용자에게 두 기록을 보여 주고 선택하게 하며 결과를 임의로 덮어쓰지 않는다.
5. seriesId는 회차를 묶는 조회 키다. 같은 series의 새 program_id에 제출·체크 완료·결과를 자동 복제하지 않는다.
6. 오프라인에서는 마지막 공고·기록을 읽되 개인 기록 변경을 막는다. 푸시 발송과 원문 확인은 오프라인 대체 동작이 아니다.

### 후순위 공식 데이터 확장

공식 준비물이나 정확한 마감 시각을 보여 주려면 Program의 공통 형식부터 확장한다. 제안 필드는 `applicationRequirements[]`(짧은 항목명·sourceUrl·checkedAt·추출 방식·검수 상태), `recruitDeadlineAt`(시간대 있는 공식 시각, 없으면 null), `lastSourceCheckedAt`(실제 상세 재확인 시각)이다. 공개 접근이 허용된 기존 출처에서 사실 항목만 추출하고 원문과 대조해 검수한다. 규칙/AI 실패·근거 없음은 null이다. 원문 전체, 제출 서류 파일, 포스터 원본을 저장하지 않는다. 구조화 항목을 넣기 위해 차단 경로나 로그인 페이지를 추가 수집하지 않는다.

이 데이터가 생기기 전에는 `이력서 PDF 필수`, `자기소개서 700자`, `18:00 마감`, `주 3시간`, `무료` 같은 공식 조건을 화면 예시에 넣지 않는다. 개인이 직접 정한 준비 기한 20:00은 공식 시간이 아니므로 별도 라벨로 사용할 수 있다.

## 5. 캔버스에 그릴 화면 9개 — 390×844

### 공통 프레임과 연결

- 프레임은 390×844px. 상태 영역 44px, 헤더 56px, 좌우 여백 20px, 본문 폭 350px.
- 기존 하단 탭 4개 `홈 / 공고 / 캘린더 / 프로필`을 유지한다. 연결은 `/`, `/programs`, `/calendar`, `/my`. 내 일정/내 정보는 화면 제목이다.
- 현재 `--nav-height`는 64px이다. 캔버스에서는 메뉴 64px + 하단 안전 영역 28px = 92px로 그린다. 상단 좌표 752px부터 고정 영역. 활성 캐릭터는 탭 아이콘 위의 예약 공간에 앉힌다.
- 목록·홈 본문의 마지막에는 92px+16px의 스크롤 여백을 둔다. 카드 `peek`가 있는 섹션은 위쪽 32px의 빈 영역을 따로 확보한다.
- 온보딩은 탭 대신 52px 시작 버튼과 안전 영역. 상세/준비는 탭 대신 64px 행동 영역+28px 안전 영역. 원문 버튼·관심 버튼의 글자 위로 캐릭터가 이동하지 않도록 별도 장식 영역을 둔다.
- 후기 화면은 상세에서 들어가는 하위 화면으로 4개 탭을 숨기고 뒤로가기를 제공한다. 필터 시트는 공고 화면 위에 열리며 배경과 탭은 조작할 수 없다.
- 각 화면의 첫 화면 범위와 스크롤 아래 영역을 구분한다. 키보드가 뜨면 입력창과 저장 버튼이 보이도록 고정 영역을 조정한다.

**누르면:** 체크→상세/홈/일정의 진행 동기화; 날짜→그날 목록; A→화면 6; B 준비→B의 화면 6; 캘린더→같은 화면 월간 변형; 제출 칩→제출만 표시; 결과 기록→직접 입력 시트; 내보내기→.ics 선택 시트. 첫 화면은 오늘 할 일과 B 마감 카드까지.

## 6. 디자인 원칙과 토큰

### 정보가 먼저, 길드는 작은 안내

1. 회색 바탕 위 흰 카드, 큰 제목, 넉넉한 여백을 유지한다. UI 강조색은 파랑 하나, 마감/오류는 빨강이다. 캐릭터의 보라·초록·금색을 새 버튼·진행 막대·상태 배지 색으로 확장하지 않는다.
2. 캐릭터 없이도 제목·문구·아이콘만으로 의미가 완결되어야 한다. 캐릭터는 `aria-hidden`, 포커스 불가, `pointer-events: none`. 안내 문구와 버튼은 접근 가능한 일반 요소다.
3. 보이는 한 화면에는 기본 **본문 안내자 최대 2명 + 활성 탭 1명**. 온보딩/소개 시트의 네 명 소개만 예외. 좁은 화면·큰 글자에서는 캐릭터를 숨겨도 내용과 버튼은 남긴다.
4. 공식 사실·일반 확인·개인 할 일·작성자 후기의 라벨을 구분한다. 정보가 없을 때 `미확인`을 쓰고 확신을 주는 캐릭터 문구를 넣지 않는다.
5. 한 영역에 주요 행동 1개. 전체 상태를 색만으로 표현하지 않고 `오늘 마감`, `제출 완료 · 본인 기록`, 체크와 라벨을 함께 쓴다.
6. 화면을 덮는 로그인/필터 시트는 헤더 바깥에 배치한다. 캐릭터가 시트 위로 올라오거나 배경 클릭을 가로채지 않는다.

### 간격·카드·버튼

- 간격 단위 4px. 사용값 4 / 8 / 12 / 16 / 20 / 24 / 28 / 32px.
- 본문 좌우 20px, 카드 안 16~20px, 행 사이 12px, 섹션 사이 28px. peek의 머리가 있는 곳은 위 32px 확보로 대체한다.
- 큰 카드·시트 모서리는 **--radius: 20px**. 목록은 기존 ProgramRow를 한 카드 안에서 재사용한다.

### 움직임과 관심 저장

- 기존의 5초 주기 깜빡임, 2.8초의 1칸 들썩임, 탭 변경의 0.45초 한 번 폴짝을 상한으로 유지한다. 큰 흔들림·반복 점프·전체 화면 효과·소리는 없다.
- 관심 저장은 **누르는 순간 처리**한다. 캐릭터가 별에 닿는 순간은 시각 연출일 뿐 저장 시작 조건이 아니다. 해당 별이 속한 목록/카드의 peek가 화면에 보이면 거기서 출발하고, 없으면 활성 탭 캐릭터를 사용한다.
- 기사 달리기·칼바람 / 궁수 활·화살 / 마법사 순간 이동·지팡이 / 성직자 기도·빛기둥의 기존 동작은 유지한다. 별 근처의 전용 공간에서만 동작한다.
- 한 번에 동작 1개. 관심 해제, 연속 저장, 출발 캐릭터 없음, 보호 영역 확보 불가, 화면 이동, 동작 줄이기는 즉시 정적인 별 상태로 처리한다. 3초 안에 끝나지 않으면 시각 상태를 확정한다.
- 저장 실패는 `관심 표시를 저장하지 못했어요 · 다시 시도`와 실제 저장 상태 복원으로 알린다. 동작 성공이 저장 성공처럼 보이지 않게 한다.
- 기기의 `prefers-reduced-motion: reduce` 또는 서비스 동작 줄이기를 적용하면 깜빡임·들썩임·탭 점프·이동·칼바람·화살·빛기둥·반짝이를 모두 멈춘다. 별과 진행 상태는 즉시 바뀌고 텍스트 안내는 남는다.
- 로딩 스켈레톤은 정적인 자리 표시를 기본으로 한다. 캐릭터가 로딩 내내 달리거나 기도하게 하지 않는다.

| 로그인 게시판 수집·robots.txt 우회·막힌 포스터 OCR | 수집 금지 원칙을 바꾸지 않는다. 공개 허용 출처만 쓰고 누락은 미확인으로 표시한다. |
| 학교·캠퍼스·사이트 주소의 코드 직접 입력 | config 기반 확장을 지킨다. 목업 학교 이름은 예시일 뿐 구현 선택지는 설정에서 읽는다. |
| 비용·요일·주당 시간·온라인·초보자 여부의 추정 필터 | 현재 구조화 데이터가 없다. 실제 태그와 기간만 활용하고 필요한 조건은 원문 확인으로 보낸다. |
| 원문 클릭으로 자동 제출·합격 판정·자동 지원 | 외부 제출과 결과를 관찰할 수 없다. 사용자가 직접 기록한다. |
| 합격 인증·참여 인증 배지·합격률 비교 | 증빙 데이터가 없고 자기 입력을 공식 사실처럼 만들 위험이 있다. 작성자 입력이라고 명시한다. |
| 공동 체크리스트·팀 역할·개인 서류 공유 | 별도 권한·초대·삭제 설계가 필요하다. 이번에는 공고 링크 공유만 유지한다. |
| 다음 회차 구독·다음 모집일 예측 | 새 공고 감지와 구독 저장을 추가하기보다 개인 지원 흐름을 우선한다. 지난 회차는 사실 목록으로만 제공한다. |
| AI 상담·심리 치료·AI 지원서 대필 | 캐릭터의 안내 역할을 넘는다. 공개 상담 프로그램/멘토링 공고를 찾아 원문으로 연결한다. |

| 네이티브 앱 개발 재개·후기 전용 하단 탭 | 현재 PWA/웹 푸시와 4개 탭을 유지해 범위를 관리한다. |

## 8. 적용 순서와 검토 기준

1. **현재 데이터로 화면 정리:** 역할 소개·학교/캠퍼스 범위 안내·오늘 브리핑·추천 근거·한 줄 요약/미확인 문구·지난 공고 연결. 개인 단계가 없는 동안 준비/제출 숫자를 가짜로 표시하지 않는다.
2. **개인 준비 흐름 연결:** applications와 준비 항목 저장, 관심→준비→제출→결과, 홈/상세/내 일정의 동일 상태, 기존 id 이동과 보관함 연결.
3. **알림과 회차 경험 확장:** 기기별 날짜 선택·중복 방지·제출 제외, 새 후기 회차 연결·기존 미지정 보존, 내 정보 설정.

출시 전에는 학교 선택과 지역 전체 선택의 차이, 캠퍼스 미확인 포함, 날짜 없는 공고, 신청 없이 참여, 체험 모드, 저장/조회 실패, 알림 차단/미지원, 제출 되돌리기, id 합치기/보관함, 회차 미지정 후기, 큰 글자/동작 줄이기를 확인한다. 캐릭터를 숨긴 상태에서도 같은 행동을 끝낼 수 있어야 한다. 수집 품질은 기존 기준인 마감일 정확도 90% 이상·잡음 5% 이하·중복 0을 이어 가며, 목표 경험의 공식 정보가 현재 데이터보다 더 정확한 것처럼 표현하지 않는다.
