# 클라우드 작업 보고

> 요약은 모든 항목이 끝난 뒤 이 자리에 적습니다.

## 검증 방법 (모든 항목 공통)

- `npm test`, `npm run typecheck`, `npm run build`를 클라우드 컴퓨터에서 실행했습니다.
- 클라우드 컴퓨터는 글꼴 서버(cdn.jsdelivr.net)에 접속할 수 없습니다. 그래서 빌드할 때만 같은 글꼴(npm의 pretendard 1.3.9 패키지에 든 같은 파일)을 컴퓨터 안에서 제공하도록 `lib/og.tsx`의 주소를 잠깐 바꿨다가 되돌렸습니다. 이 바꿈은 커밋하지 않았고, Vercel에서는 원래 주소 그대로 빌드됩니다.
- 화면은 빌드한 사이트(`next start`)를 휴대폰 크기(390×844) 브라우저로 열어 확인했습니다.

## 1. 페이지 무게 줄이기 — main에 합침

**한 일**
- 홈·공고 목록·캘린더·프로필·관리자 화면이 공고 약 1,000개를 HTML 안에 통째로 넣던 것을 없앴습니다.
  대신 목록에 필요한 칸만 담은 파일 하나(`/api/list.json`)를 빌드할 때 만들고, 다섯 화면이 그 파일을 **한 번만** 받아 같이 씁니다.
  화면을 옮겨 다녀도 다시 받지 않고, 오프라인일 때는 서비스 워커가 저장해 둔 것을 씁니다.
  - 이 화면들은 원래도 서버에서는 빈 뼈대만 그리고 내용은 브라우저에서 그렸습니다. 그래서 검색엔진에 보이는 내용은 달라지지 않습니다. 공고 상세는 그대로입니다.
  - 파일에서는 빈 값(null, 빈 목록, false)과 목록에서 쓰지 않는 칸(원문 링크, 출처, 단과대학·학과, 추출 방법)을 뺐고, 화면에서 원래 모양으로 되돌립니다(`lib/list.ts`).
  - 반복 프로그램 이름표(117KB)는 프로필에서 내 댓글이 있을 때와 관리자 화면에서만 받습니다(`/api/series-info.json`).
- 공고 목록은 처음 30개만 그리고, 끝까지 내리면 30개씩 더 그립니다. 자동으로 안 되면 "더 보기 (N개 남음)" 버튼을 누르면 됩니다. 상세 화면에서 뒤로 오면 보던 곳까지 다시 그립니다.
  필터·검색·개수는 전체 공고로 계산하므로 지금과 똑같습니다(확인: 기본 342개, "취업" 검색 54개, 마감 포함 1,006개).
- `npm run dev`도 시작 전에 데이터 파일을 만들게 했습니다(`predev`). 그래서 내 컴퓨터에서 실행해도 그대로 됩니다.
- 데이터를 못 받으면(인터넷 끊김 등) "공고를 불러오지 못했어요 / 다시 시도"가 보입니다.

## 2. 도메인 바꾸기를 설정 하나로 — main에 합침

**한 일**
- 사이트 주소를 `lib/filter.ts`의 `SITE_URL` 한 곳에서만 정하게 했습니다. 따로 적혀 있던 주소를 모두 이 값을 쓰게 바꿨습니다.
  - 알림 링크·웹 푸시 연락처: `scripts/notify.ts`의 `SITE`
  - 수집기 이름: `src/fetch.ts`의 `USER_AGENT`. 이메일도 `lib/policy.ts`의 `CONTACT_EMAIL`을 그대로 씁니다
  - 앱 데이터 주소: `mobile/src/data.tsx`의 `API_BASE` → `${SITE_URL}/api`
  - 원래부터 쓰던 곳: 사이트맵, robots.txt, 공유 미리보기 기본 주소(`app/layout.tsx` metadataBase)
- 주소 끝에 `/`를 붙여 적어도 알아서 뗍니다. 잠깐 다른 주소로 시험할 때는 환경 변수 `NEXT_PUBLIC_SITE_URL`로 덮어쓸 수 있습니다.
- **도메인을 옮길 때 할 일**: `lib/filter.ts`의 `"https://tagi-ten.vercel.app"` 한 줄을 새 주소로 바꾸고 main에 올리면 끝납니다. 그 밖에 로그인 설정(Supabase·카카오·구글)은 `docs/설정-안내.md` 5번대로 직접 해야 합니다.

**바뀐 파일**: `lib/filter.ts`, `src/fetch.ts`, `scripts/notify.ts`, `scripts/build-api.ts`(주석), `mobile/src/data.tsx`, `docs/설정-안내.md`, `CLAUDE.md`

**전후 수치**: 사이트 주소가 코드에 적힌 곳 5곳 → 1곳 (`grep tagi-ten`, 문서 제외)

**휴대폰 화면에서 확인할 곳**: 화면에서 달라지는 것은 없습니다. https://tagi-ten.vercel.app/sitemap.xml 과 /robots.txt 의 주소가 그대로인지만 보면 됩니다.
- 참고: 앱(`mobile/`)은 의존성이 클라우드에 설치되어 있지 않아 앱 쪽 타입 검사는 못 했습니다. 이미 쓰던 `@shared/filter.ts`에서 값 하나를 더 가져오는 바꿈입니다.
